# Project terminals

Use the bottom terminal toolbar to open **Services** or **Terminals**. Both tabs stay available while the panel is hidden; **Ctrl+J** hides or opens the last selected category. Terminals share this bottom panel in conversations, file editors, and diffs. Open the **projects dropdown** and click the settings button on a project row to configure its services. The project settings button is hidden when the dropdown is closed. Choose **… → Edit services…** in the Services toolbar to edit the current project directly. The same menu also offers **Worktree settings…** for the active checkout’s environment and service policy. The project and Actions menus also offer **Project services…**. An unconfigured project starts with blank Backend, Frontend, and Cloudflared entries. Select a service in the dialog's list, enter its command and **Run in folder** path, then select **Save**. Blank commands are omitted. Saving settings does not start services or change your active project.

Each service has a stable name, a command, a directory relative to the selected agent's checkout, and an optional **Restart on failure** setting. For example:

| Name | Command | Directory |
| --- | --- | --- |
| Backend | `bun run dev` | `apps/backend` |
| Frontend | `bun run dev` | `apps/frontend` |
| Cloudflared | `cloudflared tunnel run my-tunnel` | `.` |

For shared infrastructure such as databases, open **Project settings → Project defaults → Shared databases** (or **… → Project settings…** in the Services toolbar). Each database has a name, a start command, a folder, a ready check and a timeout. They are edited only there and saved with the worktree setup workflow; the service editor lists them read-only with an **Edit in Project settings** link. Saving databases never changes app services, and saving app services never changes databases, so each editor preserves the other's settings even when a dialog was opened before the other one saved. A database starts in the main project folder and stays there for every worktree. Selecting a conversation in the project starts its databases if they are not running. Zeron retries its ready check in that folder until it exits successfully (120 seconds by default); setup, migrations and app services wait for it. The Services panel shows databases first, with a drive icon, and reports **Starting…**, **Ready** or **Not ready**; a failed start, timeout or cancellation keeps its output and error. **Stop app services** stops the active worktree's app services and keeps databases running; switching or removing worktrees also keeps them running. **Stop all, including databases** stops them too.

The toolbar combines **Start/Stop** for the selected service with an attached **…** menu. That menu offers **Restart** for the selected service, **Start all services**, **Restart all services** (**Restart app services** when databases are configured), **Stop all services** (or **Stop app services** and **Stop all, including databases**), **Edit app services…**, and **Project settings…**. Hover a control to see the service it acts on. Starting an already running service reuses its process. Each service has its own terminal output and input. Hiding the panel leaves services running. Switching between agents in the same project moves running services to the selected agent's checkout: the old service sessions stop and release their ports before replacements start. Stopped services stay stopped; two agents in the same checkout reuse the processes. A session using the main checkout runs services from the project's main folder. The new-chat page does not activate services or show terminals. Background status polls do not move services; the foreground window's agent selection and focus determine the active checkout. Status keeps refreshing while an action or a worktree switch is in progress. **Services** are shared by the project; **Terminals** are regular per-chat terminals with their own tabs and a new-terminal button. Switching categories preserves running services, shells, and their output. Project actions also open in Terminals.

Use foreground commands: a command that backgrounds its server finishes immediately, and its remaining children are stopped. Commands run in the owning device's login shell, with `ZERON_PROJECT_ROOT` set to the registered main folder and `ZERON_CHECKOUT_ROOT` to the active checkout. Directories must exist inside that checkout; an agent checkout must be the main folder or a verified linked Git worktree. If a handoff cannot start a service because its directory is missing, the old services stay stopped and the terminal panel reports the error. Each service tab has a status dot. The command and relative folder appear beside the tabs when there is room; hover a tab for its full status, command, folder, checkout, and exit information. The toolbar summarizes running, retrying, and failed services. Controls occupy two compact rows, leaving the rest of the panel for output. Project settings now provide [worktree environment preparation and service concurrency policies](worktree-environments.md). Commands inherit configured checkout variables and can load that checkout’s env files.

Terminals and services use the cached PATH from an interactive login shell, followed by any extra folders from the app's own PATH. This makes Homebrew and shell-managed development tools available even when the app opens from the desktop and services run non-interactively. When both provide a tool with the same name, the copy your shell would pick wins. A checkout's explicit `PATH` variable takes precedence. Service commands are POSIX shell commands: bash, zsh, and other POSIX login shells run them as login shells, and fish runs them directly. If your login shell is csh, tcsh, nu, or another shell that cannot run them, services and workflow commands run with `/bin/sh` and the same login PATH instead.

Service profiles are private to the owning engine's `project-terminals.json`, rather than committed into your repository or synced to the registry. It is the single saved list of a project's app services and databases; a worktree's own app services are stored with its worktree settings. Older versions also kept a copy of the project's services in worktree settings. On first use that copy is adopted only if the profile has no app services, then removed; the previous `settings.json` is kept as `settings.json.before-service-migration-<timestamp>`. If that file cannot be read, the engine renames it to `project-terminals.json.invalid-<timestamp>` and starts with no saved services, so the old profiles can be recovered by hand. Saved service groups for worktree folders that no longer exist are dropped when the engine starts. Up to 12 services can be saved per project. Editing a running service's command or directory applies on its next start; removing one stops it.

A zero exit code is shown as successful completion. A nonzero exit code is shown as a failure and retains the terminal output. Optional automatic recovery makes at most three restart attempts, after 1, 2, and 4 seconds. A service that ran for at least a minute before failing gets the full three attempts again, so only crash loops reach the limit. If a restart cannot start at all, for example because its folder was removed, the service shows as failed and keeps the previous run's output. Stop cancels pending recovery and stops the service's whole Linux PTY session, including child development servers in separate job groups. The service's processes first receive SIGTERM so they can release ports and save state; anything still running after 3 seconds receives SIGKILL. Stop waits for those processes to exit before reporting **Not running** or starting replacements; unrelated services and regular shells are left running. The toolbar displays stopping progress, and a Stop failure remains visible across status refreshes. Stopped output is retained with a stopped marker. Quitting the engine stops managed services; closing the last Zeron window waits (up to 30 seconds) until agents and services have stopped, so no windowless engine is left running for the next launch to attach to. If the engine is interrupted, the next launch reports interrupted runs and waits for you to start them.
