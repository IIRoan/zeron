# Project terminals

Use the bottom terminal toolbar to open **Services** or **Terminals**. Both tabs stay available while the panel is hidden; **Ctrl+J** hides or opens the last selected category. Terminals share this bottom panel in conversations, file editors, and diffs. Open the **projects dropdown** and click the settings button on a project row to configure its services. The project settings button is hidden when the dropdown is closed. The gear in the terminal toolbar also opens the dialog. The project and Actions menus also offer **Project services…**. An unconfigured project starts with blank Backend, Frontend, and Cloudflared entries. Select a service in the dialog's list, enter its command and **Run in folder** path, then select **Save**. Blank commands are omitted. Saving settings does not start services or change your active project.

Each service has a stable name, a command, a directory relative to the selected agent's checkout, and an optional **Restart on failure** setting. For example:

| Name | Command | Directory |
| --- | --- | --- |
| Backend | `bun run dev` | `apps/backend` |
| Frontend | `bun run dev` | `apps/frontend` |
| Cloudflared | `cloudflared tunnel run my-tunnel` | `.` |

The toolbar has Start/Stop and Restart controls for the selected service. Its **…** menu offers **Start all services**, **Stop all services**, and **Restart all services**. Hover a control to see the service it acts on. Starting an already running service reuses its process. Each service has its own terminal output and input. Hiding the panel leaves services running. Switching between agents in the same project moves running services to the selected agent's checkout: the old service sessions stop and release their ports before replacements start. Stopped services stay stopped; two agents in the same checkout reuse the processes. A session using the main checkout runs services from the project's main folder. The new-chat page does not activate services or show terminals. Background status polls do not move services; the foreground window's agent selection and focus determine the active checkout. **Services** are shared by the project; **Terminals** are regular per-chat terminals with their own tabs and a new-terminal button. Switching categories preserves running services, shells, and their output. Project actions also open in Terminals.

Use foreground commands: a command that backgrounds its server finishes immediately, and its remaining children are stopped. Commands run in the owning device's login shell, with `ZERON_PROJECT_ROOT` set to the registered main folder and `ZERON_CHECKOUT_ROOT` to the active checkout. Directories must exist inside that checkout; an agent checkout must be the main folder or a verified linked Git worktree. If a handoff cannot start a service because its directory is missing, the old services stay stopped and the terminal panel reports the error. Each service tab has a status dot. The command and relative folder appear beside the tabs when there is room; hover a tab for its full status, command, folder, checkout, and exit information. The toolbar summarizes running, retrying, and failed services. Controls occupy two compact rows, leaving the rest of the panel for output. Project settings now provide [worktree environment preparation and service concurrency policies](worktree-environments.md). Commands inherit configured checkout variables and can load that checkout’s env files.

Terminals and services inherit the app's PATH plus the cached PATH from an interactive login shell. This makes Homebrew and shell-managed development tools available even when the app opens from the desktop and services run non-interactively. A checkout's explicit `PATH` variable takes precedence.

Service profiles are private to the owning engine's `project-terminals.json`, rather than committed into your repository or synced to the registry. Up to 12 services can be saved per project. Editing a running service's command or directory applies on its next start; removing one stops it.

A zero exit code is shown as successful completion. A nonzero exit code is shown as a failure and retains the terminal output. Optional automatic recovery makes at most three restart attempts, after 1, 2, and 4 seconds. Stop cancels pending recovery and terminates the service's whole Linux PTY session, including child development servers in separate job groups. It waits for those processes to exit before reporting **Not running** or starting replacements; unrelated services and regular shells are left running. The toolbar displays stopping progress, and a Stop failure remains visible across status refreshes. Stopped output is retained with a stopped marker. Quitting the engine stops managed services. If the engine is interrupted, the next launch reports interrupted runs and waits for you to start them.

# Committing a new branch

The Source Control commit dropdown offers **Commit & Publish Branch** when the branch has no upstream. This commits staged files with your message, pushes the branch, and sets its upstream in one action. Subsequent commits use **Commit & Push**; the main button and Ctrl+Enter retain the selected action for the current checkout view.

Publication honors Git's configured push destination, then prefers `origin`, then a single enabled remote. With multiple possible destinations and no default, choose a remote before the commit begins. Remotes with a push URL of `DISABLED` are excluded. Publication never force-pushes. If the network push fails after the commit succeeds, the commit remains local and Source Control reports the failure so you can retry Push.

The dock uses Zeron's existing 200 ms pane transition, 150 ms tab and content fades, and animated hover treatments. Status polling does not replay the content fade. Reduced-motion settings snap these transitions to their final state.
